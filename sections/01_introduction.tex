\section{Introduction}
\label{sec:introduction}

This paper studies the performance of determinant evaluation over the finite field \(11^3\) which contains \(1331\) elements.
The program fills two \(n \times n\) matrices \(A\) and \(B\) with seeded random elements, computes \(C = AB\), and evaluates \(\det(A)\), \(\det(B)\), and \(\det(C)\) using Gaussian elimination. Additionally, it verifies the identity:
\[
\det(C) = \det(A)\det(B).
\]
Each field element is a polynomial of degree less than three with coefficients modulo 11.
Every addition and multiplication, therefore, requires polynomial arithmetic followed by reduction modulo an irreducible cubic, while reciprocals require the extended-Euclidean computation.
Because the matrix multiplication and determinant evaluation use cubic scale numbers (\(n^3\)) of these operations, finite-field arithmetic dominates the execution time.

The implementation is divided across three sections: a
\href{https://github.com/hoop3r/group2-algebra-assignment}{driver repository},
a matrix library, and a
\href{https://github.com/JacobNance142/algebra-finite-fields-group2}{finite-field library}.
The goal of this work is to make it reduce field-operation costs without restructuring the dependency chain or public interfaces.
Since the field only contains 1331 elements, the results of every possible sum and product can be precomputed and later looked up.
thus, we replace the finite-field element implementation with a cached, API-compatible class and distribute the determinant evaluation across machines with MPI.

The paper addresses three primary questions:
\begin{enumerate}
  \item Which classes have the highest sequential cost so should be cached and where do they sit in the dependency chain?
  \item How do runtime and peak memory change when lookup based/cached arithmetic replaces the original implementation?
  \item At what matrix size is the measured MPI determinant faster than the cached sequencial implementation?
\end{enumerate}

Caching the finite-field element class reduced a \(512 \times 512\) run resulting in a speed up of approximately \(26 \times\), while increasing peak memory by approximately 7\,MB.
An eight-rank MPI determinant was approximately as fast as the cached sequential determinant implementation at \(n = 512\), but was faster at \(n = 768\), and was \(1.6 \times\) faster at \(n = 2048\).
Section~\ref{sec:chain} describes the dependency chain, Sections~\ref{sec:cache} and~\ref{sec:results} present the cache and its measurements, Sections~\ref{sec:mpi} and~\ref{sec:mpi-results} describe the MPI determinant and its measurements, and Section~\ref{sec:conclusions} concludes.
